01

Functional Specification — Customer App

Every module below reflects the live platform and the Customer Figma design, cross-checked screen by screen. Items marked confirmed are live and working today; gap marks scope that isn't on the live platform yet, deferred rather than assumed.

Catalog & Navigation

CUST-01
confirmed
  • 19 categories total (11 top-level + 8 under "More"), each opening a mega-menu of up to 11 subcategories
  • Category listing pages: subcategory chips, price-range filter, star-rating filter, multi-select brand filter, 5-way sort (Featured / Price ↑ / Price ↓ / Rating / Newest)
  • Search with the same faceted filters
  • Flash Deals page: shared countdown timer across listed deals, per-product "% sold" progress bar
  • Homepage sections (promo banners, curated collections, top brands, trust-signal strip) render content that's managed entirely from the existing web Admin panel — no new admin work needed for the Customer app to display it

Product Detail

CUST-02
confirmed
  • Image gallery, price + discount badge, stock urgency messaging ("only 1 left")
  • Per-product seller attribution card (confirmed genuine multi-vendor)
  • Ratings and reviews, including photo/video review attachments and category-specific review attributes (e.g. fragrance longevity/projection) where sellers have supplied that data
  • Variant selector (size/color/etc.), generic rather than hardcoded — handles whatever variant types a seller lists
  • Freeform specification blocks (top notes, care instructions, etc.) sourced from the seller's product listing

Wishlist

CUST-03
confirmed
  • Dual behavior: heart icon on product cards toggles anonymously (local/optimistic UI, no login prompt)
  • Full wishlist list page is login-gated, with price-drop and stock filters, and a "move all to cart" action

Cart & Checkout

CUST-04
confirmed
  • Slide-out cart drawer + full cart page; VAT-inclusive pricing (5% UAE VAT); free-shipping threshold nudge
  • Shipping: address types (Home/Office/Other), Emirate + City cascading select; saved addresses persist to account
  • Payment: Tap Payments integration (Card, Apple Pay, Google Pay), Tabby and Tamara (buy-now-pay-later), and a separate Cash on Delivery option (adds AED 10 handling fee)
  • Platform-wide coupon code field; one coupon per order, excluded on Flash Deal items
  • Multi-vendor orders itemize shipping per seller
  • Delivery speed selection (Standard / Express)
Two items are open questions, not yet priced: a saved-card / tokenized payment option (CVV re-entry on a stored card) — pending confirmation on whether this runs through Tap Payments' own hosted vault or requires custom secure storage; and a "YallaPlatinum" membership perk shown on Express delivery (a loyalty/membership tier concept) — pending scope and timing before it's costed.

Account Area

CUST-05
confirmed
  • Profile Settings — name, phone, saved addresses (multiple, typed), change password, Personal Details & KYC (optional, not a hard gate)
  • Order History — status-tabbed, live order tracking with a delivery-journey timeline
  • Returns — dedicated list view tied to completed orders
  • My Reviews — purchase-gated review submission
  • Payment Methods, Language toggle (UI present, full Arabic content pipeline deferred — see CUST-07), WhatsApp order-update toggle, Face ID & Passcode

Auth

CUST-06
confirmed
  • Google OAuth + email/password, with mandatory email verification step before first login
  • Server-side weak/breached-password rejection on signup
  • Backend runs on Lovable Cloud (Supabase-based)

Localization

CUST-07
deferred — not in this scope/cost
  • No language switcher on the live platform — English only, currently
  • Arabic/English localization is in progress on the web platform but not live yet, so there's no live reference to build against — out of this scope and cost rather than assumed
  • Layout is built RTL-aware from the start, so localization can switch on later at low cost instead of a layout retrofit

Buyer-Seller Messaging

CUST-08
confirmed — live reference exists
  • Live on the web platform as product enquiries — a conversation thread tied to a product, with file attachments and email notification on new messages
  • Real-time delivery via Supabase Realtime, matching the platform's existing messaging protocol
  • Mobile build: conversation list, thread view, send/receive, read/unread state, plus a push notification tie-in for new messages

Ratings, Reviews & Rewards touchpoints

CUST-09
confirmed
  • Structured review form: overall rating, quick-highlight tags, category-specific attributes, photo/video attachments, courier-delivery rating
  • Public-review toggle (display name + verified-buyer/city badge)
Not priced: a "YallaPoints" loyalty balance and earning/redemption mechanic appears throughout the design (product detail, checkout, order confirmation, profile, reviews) — already confirmed deferred, not in this phase. The Customer app screens reference it cosmetically; the underlying points ledger and redemption logic are out of scope until the client decides to build it.

Notifications

CUST-10
confirmed
  • Transactional/order-status push and in-app notifications (delivery updates, price drops on wishlisted items, points credited, review responses)
Not priced: promotional/marketing-campaign notifications (time-limited offer pushes with their own copy and voucher code, e.g. a flash-sale announcement) would need a campaign-composer control in the Admin panel that doesn't exist today — see the Admin Panel section. Out of this estimate until confirmed as needed.
02

Admin Panel & Backend — What the Customer App Needs

No Admin mobile app is being built in this phase. The Customer app instead reads content that's managed through the existing web Admin panel and backend — the same platform already live and reviewed firsthand. Content the Customer app needs falls into three groups: already covered as-is, covered but needs a mobile-specific option, and genuinely new.

Already covered, no new work needed — Trending Products, Curated Collections content, the platform-wide promo/coupon banner, and shipping settings are already manageable in the existing web Admin panel exactly as the Customer app needs them. The mobile app simply reads the same data the website already reads.

Mobile-Visibility Controls

ADM-EXT-01
scoped — minimal
  • Top Brands and Featured Collections exist in the Admin panel already, but the mobile app needs its own curation, separate from what shows on the website (e.g. a different brand lineup or collection order for the app)
  • Scoped minimally: a "Show on Mobile" flag added to the existing Brands and Collections admin tables, so the same records can be curated differently for web vs. app without duplicating the underlying data or building a parallel management screen

Similar Bought Product

ADM-EXT-02
scoped — minimal
  • New to the Customer app, not present on the website — a "customers also bought" style section
  • Scoped minimally as a rule-based backend query (same category / same brand, excluding the current product), exposed as a new API endpoint — no machine-learning recommendation engine, no new Admin screen. This keeps the section functional without the larger build a true recommendation system would need

Add-from-Wishlist Quick Action

ADM-EXT-03
scoped — minimal
  • New to the Customer app — a one-tap "move to cart" action directly from the wishlist, rather than opening each product first
  • Backend: a wishlist-to-cart endpoint (add to existing cart logic, remove from wishlist on success). Purely a customer-facing action — no Admin control needed

Promotional Push Notification Composer

ADM-EXT-04
scoped — minimal
  • The Customer Figma design shows marketing-style push notifications (e.g. a time-limited flash-sale announcement with its own copy and voucher code) — distinct from transactional order-status notifications, which are already covered (see CUST-10)
  • Scoped minimally: a single Admin screen to author and send a push (title, body, optional voucher code, send-now) plus the mobile-side registration to receive it. Scheduling and audience-targeting are kept out of this pass to stay within scope — send-now to all app users covers the flash-sale-announcement use case shown in the design
Kept out of this number — Any further mobile-only sections beyond ADM-EXT-02/03/04 are deferred to a later phase to keep this estimate within budget. Scheduled/targeted push campaigns (beyond send-now-to-all) are also deferred, for the same reason.
