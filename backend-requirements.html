Backend Requirements for Mobile

Based on a review of the current codebase, here's what's already in good shape for mobile integration, and what still needs to be built on the backend side before the mobile app can rely on it.

What's already mobile-ready

No changes needed here — the mobile app can integrate directly against what exists today.

Authentication
Ready

API access is already token-based (Bearer token via Supabase Auth), not tied to a web session cookie. This is exactly the pattern a mobile app needs — no separate mobile auth flow has to be built on the backend side.

Core data access
Ready

Products, orders, sellers, and most other core data are accessed directly via the Supabase client SDK with Row-Level Security — the same approach the web app uses. Mobile will integrate the same way; there's no separate "mobile API" to build for basic reads and writes.

What still needs backend work

These are gaps that need backend-side work before the mobile app can depend on them.

Push notifications
Needs building

There's currently no push notification infrastructure — no device-token registration or storage, and no FCM (Android) or APNs (iOS) integration. Today, notifications go out as email and an in-app bell only.

The good news: a clean notification-event list already exists in the codebase (new_order, order_shipped, payout_processed, and others), which can be reused as the trigger points once push delivery is added — this isn't a redesign, just a new delivery channel on top of events that are already fired.

  • Needs: a device-token storage table/endpoint (mobile registers its push token on login)
  • Needs: FCM + APNs dispatch wired to the existing notification events
WhatsApp order notifications
Needs building

Not built yet — this is the WhatsApp Business API integration discussed separately (seller alert on new order, customer alert on dispatch). Like push notifications, this can hook into the same order-create and dispatch events already firing in the system; it just needs the WhatsApp Business API account and the trigger logic added.

Payment gateway migration
In progress

The current codebase has Stripe live in production. Confirmed this is actively being migrated to Tap Payments — flagging here so the mobile checkout build is timed against whichever gateway is live when that work starts, rather than assuming Tap Payments is already in place.

This list reflects a code review of the current repository snapshot, not a live walkthrough — if any of this has moved since, let us know so the mobile scope stays aligned with what's actually live.
