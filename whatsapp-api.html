WhatsApp Business API — What to Purchase

For sending order-status alerts (new order → seller, dispatch → customer). This is account setup and message-sending infrastructure, handled server-side by the backend — not a mobile app dependency.

The API

There's only one underlying API for this: WhatsApp's own Business Platform (Cloud API). Every provider — Meta directly, or a reseller like Twilio or Gupshup — sends messages through this same API. The choice isn't "which API," it's "which provider account to set it up through."

Recommendation

Go with Twilio's WhatsApp Business API. It's the most widely used route to Meta's Cloud API, has the most complete setup documentation, and gets a working number live the fastest. Meta's Cloud API directly is cheaper per message long-term but needs more manual setup (Meta Business verification, template approval handled without a provider's guidance) — not worth the extra effort for this use case.

What to actually do

StepWhat it means
1. Create a Twilio account Sign up at twilio.com — this is the account/billing the client owns.
2. Enable WhatsApp Business API Inside Twilio, request WhatsApp API access and connect (or register) a business phone number.
3. Get message templates approved Meta requires pre-approved templates for automated messages (e.g. "Your order #1234 has been dispatched") — Twilio guides this approval process.
4. Hand credentials to the backend team Once active, the backend team uses Twilio's API keys to trigger the two message types (new order, dispatched) directly from the server — no mobile app involvement.
Account creation, verification, and per-message billing are all on the client's side through Twilio. On the app side, the only requirement is that phone numbers are already being collected — which they are, as part of the existing profile scope. No separate mobile-app integration work or cost applies here.
