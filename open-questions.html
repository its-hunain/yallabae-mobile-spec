Q1

Product Detail "Notes" (fragrance pyramid) card

open

Figma shows: Top Notes / Heart Notes / Base Notes for a mockup product ("La Luna Eau De Parfum") that doesn't exist in the real database.

Checked: scanned 100+ real products' specifications — no product anywhere has Top/Heart/Base Notes fields. Real fragrance products only have generic fields (Brand, Volume, Longevity, Gender) and sometimes a single "Scent" word or a freeform "Scent Personality" paragraph — nothing tiered.

Current status: built with the real card structure (icon, title, category badge, description, tiered rows), but the tier content always shows a "backend pending" placeholder since no real data exists.

Question

Should fragrance products get a real Top/Heart/Base Notes data model (new fields on the product form), or should this card be re-scoped/removed for mobile?

Q6

All Products Page header (Home-style vs. back-button)

open

Figma shows: the "All Products Page" uses the exact same header as Home - logo, notifications bell, wishlist heart, profile avatar (no back button).

Built as: a back-button header instead (chevron + centered title "All Products" / the category name), matching every other destination screen (Category listing, Product Detail) - because this page is only ever reached BY NAVIGATING to it (from Home's "View All", Product Detail's "Similar Products"/"Frequently Bought Together" links, category pills, etc.), never as a tab-bar root screen the way Home is. Without a back button, there's no way back to wherever the user came from.

Question

Was the Home-style header on this screen intentional (e.g. is "All Products" meant to be reachable as its own tab-bar destination, not just a drill-down page?), or is this a design oversight and the back-button header is the right call?
